
# Описание API

## Cryptography Service

API методы для сервиса криптографии

### Получить 256-битный хеш

**Метод:** `GET`  
**URL:** `api/cryptography/hash/get256BitHash`

**Заголовки:**

- `Content-Type`: `application/json` - указывает, что в теле запроса придет JSON-объект

**Тело запроса:**

```json
{
"algorithm": "",
"data": ""
}
```

**Обязательные параметры тела запроса**:  

- **algorithm** - название алгоритма для хеширования. На данный момент поддерживается только `GOST`
- **data** - представление битов файла в 16-ом виде в формате строки. По этим данным происходит хеширование

**Ответы:**

**Формат ответа в случае ошибки выполнения запроса**:
```json
{
  "error": {
    "message": ""
  }
}
```

**message** - код ошибки

**HTTP 400:** не все обязательные параметры тела запроса присутствуют  
**HTTP 500:** внутрення ошибка сервера. Может произойти в случае необработанной ошибки на стороне сервера

**Формат ответа в случае успешного выполнения запроса:**

```json
{
    "hash": ""
}
```

**hash** - хеш в формате строки

**HTTP: 200** запрос выполнился успешно

## File storage service

API методы для сервиса файлового хранилища

### Получить существующие файловые хранилища

**Метод:** `GET`  
**URL:** `api/fileStorage/getStorages`

**Заголовки:**

- `Content-Type`: `application/json` - указывает, что в теле запроса придет JSON-объект

**Тело запроса:**

```json
{
  "type_id": ""
}
```

**Необязательные параметры тела запроса**:

- **type_id** - id типа файлового хранилища. Нужен в случае, если нужно получить файловые хранилища определенного типа. Список идентификаторов:
  - `database` - представляет из себя файловое хранилища типа **ключ-значение**, являющееся таблицей внутри данной базы данных. Ключ - id файла, значение - тела в 16-ом представлении.
  - `filesystem` - представляет из себя файловое хранилище хранящее метадату о сервере, куда сохраняется файл. В ней хранится ssh ключ и директория на сервере
  - `batchStorage` - представляет из себя распределенное файловое хранилище, нодами которой служат файловые хранилища другого типа (**нельзя делать нестинг batchStorage'ей**) 

**Ответы:**

**Формат ответа в случае ошибки выполнения запроса**:
```json
{
  "error": {
    "message": ""
  }
}
```

**message** - код ошибки

**HTTP 400:** не все обязательные параметры тела запроса присутствуют  
**HTTP 500:** внутрення ошибка сервера. Может произойти в случае необработанной ошибки на стороне сервера

**Формат ответа в случае успешного выполнения запроса:**

```json
{
    "storages": [
      {
        "id": -1,
        "name": "",
        "type_id": ""
      }
    ]
}
```

**storages** - список с хранилищами

**id** - id хранилища в базе данных  
**name** - имя объекта хранилища, например: **db_partition_001**  
**type_id** - id типа файлового хранилища

**HTTP: 200** запрос выполнился успешно

## Workflow Service

API методы для сервиса работы с бизнес процессами

### Отфильтровать задачи бизнес процесса

**Метод:** `GET`  
**URL:** `api/workflow/filter`

**Заголовки:**

- `Content-Type`: `application/json` - указывает, что в теле запроса придет JSON-объект

**Тело запроса:**

```json
{
  "object_id": "",
  "filter": ""
}
```

**Обязательные параметры тела запроса**:

- **object_id** - id объекта, по которому построен бизнес-процесс

**Необязательные параметры в теле запроса:**:

- **filter** - фильтр формата RSQL, которые строится исходя из действий пользователя, например:  
`(name=in=("Задача 1", "Задача 2");respEmp=="Иванов Иван Иванович"),startDate=gt=2025-02-13T01:00:00`

**Ответы:**

**Формат ответа в случае ошибки выполнения запроса**:
```json
{
  "error": {
    "message": ""
  }
}
```

**message** - код ошибки

**HTTP 400:** не все обязательные параметры тела запроса присутствуют  
**HTTP 500:** внутрення ошибка сервера. Может произойти в случае необработанной ошибки на стороне сервера

**Формат ответа в случае успешного выполнения запроса:**

```json
{
    "tasks": [
      {
        "id": -1,
        "name": "",
        "respEmpIds": [
          {
            "id": -1,
            "name": ""
          }
        ],
        "startDate": "YYYY-MM-DDTHH:mm:ss",
        "endDate": "YYYY-MM-DDTHH:mm:ss",
        "deadline": "YYYY-MM-DDTHH:mm:ss",
        "commentary": ""
      }
    ]
}
```

**tasks** - запущенные или выполненные задачи в бизнес процессе

**id** - id задачи бизнес процесса  
**name** - название задачи  
**respEmpIds** - исполнители задачи с **id** и их именем  
**startDate** - время взятие задачи в работу  
**endDate** - время, когда задача была выполнена  
**deadline** - крайний срок выполнения задачи  
**commentary** - комментарий к задаче

**HTTP: 200** запрос выполнился успешно
